1. SYSTEM OVERVIEW & ARCHITECTURAL HIGHLIGHTS
================================================================================
The Parul University Smart Management Information System (SMIS) Portal is a comprehensive, institutional-grade academic
enterprise platform engineered to streamline the entire university lifecycle across
three key stakeholder groups: Students, Faculty Instructors, and Academic
Administrators.

The platform eliminates the legacy friction of fragmented academic portals by
unifying daily operations into a responsive, single-page application (SPA) backed
by an event-driven Node.js gateway.

CORE ARCHITECTURAL PILLARS:
1. Strict Role Segregation (Zero-Overlap Security):
   Independent namespaces for each role (/student, /faculty, /admin). A student
   session is cryptographically and logically restricted from invoking faculty or
   administrative operations.
2. Deterministic 1-Hour Inactivity Auto Sign-Out:
   Complies with campus terminal safety standards. An inactivity engine tracks user
   input and automatically logs out idle sessions after 60 minutes (3,600,000 ms),
   with a 5-minute visual countdown warning modal.
3. Sub-100ms Dual-Channel Real-Time Data Sync:
   Implements a hybrid bus combining WebSockets (Node.js 'ws' engine) and the
   browser BroadcastChannel API ('PU_ERP_REALTIME_BUS'). Faculty attendance submissions
   or outpass approvals propagate instantly to student dashboards without page reloads.
4. High-Definition Printable Grade Cards:
   Full client-side PDF export pipeline rendering official transcripts complete
   with University Crest, Security Barcode, Verification QR Code, and digital
   signatures from the Controller of Examinations.

4. CENTRAL AUTHENTICATION & 1-HOUR IDLE TIMEOUT SECURITY
================================================================================
4.1 STRICT ROLE-BASED ACCESS CONTROL (RBAC):
The login page provides dedicated tabs for Student, Faculty, and Admin personas:
- Students authenticate via 12-digit Enrollment No (e.g. 210303105001) or Email.
- Faculty authenticate via Employee ID (e.g. PU-FAC-3012, PU-FAC-8821) or Email.
- Admins authenticate via Admin ID (e.g. PU-ADM-001) or Registrar Email.
Public registration enforces verification against pre-authorized Master Rosters.
Admin accounts cannot be self-registered; they are restricted to registrar issuance.

4.2 DETERMINISTIC 1-HOUR INACTIVITY AUTO SIGN-OUT:
To prevent unauthorized access on shared campus laboratory terminals:
- Time Duration: 60 minutes = 3,600,000 milliseconds.
- Passive Interaction Monitoring: Attaches throttled event listeners to:
  'mousemove', 'keydown', 'click', 'scroll', 'touchstart'.
- Continuous Reset: Any user activity updates 'lastActivityTime = Date.now()'.
- Real-Time Topbar Widget: Displays a live ticking countdown pill:
  "Session: 01:00:00" -> "Session: 00:54:12", etc.
- 5-Minute Critical Warning Modal: When remaining time drops to <= 5 minutes
  (300,000 ms), a high-visibility security alert modal pops up with a large
  countdown timer and a "Keep Me Signed In" action.
- Auto Sign-Out & Redirection: When the timer hits 00:00, the session token is
  wiped, local storage is cleared, and the browser redirects to:
  "/?session_expired=true", triggering a prominent notification banner.
- Reviewer Fast-Forward Button: The topbar includes a "⚡ Test 1-Hour Timeout"
  button to immediately simulate timeout expiration for evaluation purposes.

5. DYNAMIC REAL-TIME DATA BUS & DUAL-CHANNEL CDC SYNC
================================================================================
The SMIS Portal employs a dual-channel real-time pub/sub synchronization pipeline:

PRIMARY CHANNEL: Native WebSocket Hub
- Runs on ws://localhost:3000 alongside Express.
- Broadcasts JSON-encoded academic events to all connected clients across devices.

SECONDARY CHANNEL: HTML5 BroadcastChannel API
- Operates on channel name 'PU_ERP_REALTIME_BUS'.
- Guarantees instantaneous, zero-latency cross-tab communication on the same browser
  even in offline or low-connectivity environments.

AUDIO SYNTHESIS: Web Audio API
- When academic updates occur (e.g. attendance marked, outpass approved, results
  published), the client uses an oscillator to generate a pleasant, two-tone
  educational chime (523.25 Hz [C5] -> 659.25 Hz [E5]) without external audio files.

CORE EVENT SPECIFICATIONS:
+--------------------------+-----------------+-------------------+-----------------------------------------+
| Event Key                | Originator Role | Target Role       | Impact / UI Action                      |
+--------------------------+-----------------+-------------------+-----------------------------------------+
| ATTENDANCE_UPDATED       | FACULTY         | STUDENT, ADMIN    | Recalculates subject %, chimes, logs CDC|
| OUTPASS_STATUS_CHANGED   | FACULTY         | STUDENT, ADMIN    | Updates status, renders QR Gatepass     |
| EXAM_RESULTS_PUBLISHED   | ADMIN           | STUDENT, FACULTY  | Unlocks Grade Card PDF download         |
| AUDIT_LOG_ADDED          | SYSTEM          | ADMIN             | Prepends row to live CDC Audit Stream   |
+--------------------------+-----------------+-------------------+-----------------------------------------+

7. AUTOMATED ATTENDANCE & OFFICIAL GRADE CARD PIPELINE
================================================================================
7.1 ATTENDANCE AGGREGATION ALGORITHM:
Attendance compliance is calculated dynamically using relational aggregation:
   Percentage = (Attended Lectures / Total Lectures Held) * 100
- If Percentage >= 75%: Student is granted "Exam Eligible" clearance.
- If 70% <= Percentage < 75%: Student receives a "Shortage Warning" notice.
- If Percentage < 70%: Student is flagged as "Detention Risk" requiring proctor review.

7.2 OFFICIAL GRADE CARD PDF GENERATION WORKFLOW:
1. Faculty records Continuous Internal Evaluation (CIE) and Mid-Sem marks.
2. Controller of Examinations enters End-Semester examination marks.
3. Administrator executes the Result Publishing Engine.
4. System computes SGPA per the official UGC formula:
   SGPA = Sum(Course_Credits * Grade_Points) / Sum(Course_Credits)
5. The student accesses the "Results" tab and clicks "Download Official Grade Transcript".
6. The client renders an official Parul University Statement of Grades modal featuring:
   - High-resolution University Crest & Gold Seal
   - Student Bio-Data, Enrollment Number & Examination Seat Number
   - Course-wise Credit & Letter Grade Distribution
   - Calculated Semester SGPA & Cumulative CGPA
   - Security Barcode and Verification QR Code
   - Digital signature of the Controller of Examinations
7. The user clicks "Print / Save as PDF", triggering the browser's native print engine
   optimized with clean print media queries ('css/print.css').

11. SYSTEM AUDIT, TROUBLESHOOTING & FAQS
================================================================================
Q1: Can I run this offline without an active internet connection?
A1: Yes! The system is completely self-contained. The fonts fall back gracefully to
    system sans-serif / monospace, all university images are packaged locally in
    'public/assets/', and audio alerts use client-side Web Audio API synthesis.

Q2: Does the real-time sync work if WebSockets are blocked by a campus firewall?
A2: Yes! The architecture features a dual-channel design. If WebSockets are blocked,
    the HTML5 BroadcastChannel API automatically handles instant synchronization
    across all browser tabs on the local machine.

Q3: How do I reset all data back to original default demo seeds?
A3: Simply open your browser Developer Tools (F12) -> Application -> Local Storage ->
    Clear All, and restart the Node.js server via terminal.

Q4: What browser versions are supported?
A4: All modern evergreen browsers including Google Chrome 90+, Microsoft Edge 90+,
    Mozilla Firefox 88+, and Safari 14+.
